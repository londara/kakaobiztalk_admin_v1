## 4. 트러블슈팅

### 4.1 헬스 체크 실패

**증상**: `/health` 가 500 반환

**점검 순서**:
1. 서비스 프로세스 살아있는지 (`ps aux | grep <service>`)
2. DB 연결 가능한지 (`psql -h ... -c 'SELECT 1'`)
3. 메시징 큐 연결 가능한지
4. 의존 외부 시스템 헬스 (각 외부 API)

**복구**:
- 단일 인스턴스 장애 → 자동 재시작 대기 (30 초)
- 다수 인스턴스 장애 → §5 장애 대응 절차로 escalate

### 4.2 응답 지연 (P95 > 1s)

**점검 순서**:
1. CPU / 메모리 사용률 (`top` / `htop`)
2. GC 로그 (Java 의 경우)
3. DB slow query 로그
4. 외부 API 응답 시간

**복구**:
- DB 인덱스 점검
- 캐시 워밍업
- 수평 확장 (`kubectl scale`)

### 4.3 외부 API 장애

**점검 순서**:
1. 외부 시스템 상태 페이지
2. 큐 적재 여부 (재시도 큐)
3. Circuit Breaker 상태

**복구**:
- 자동 재시도 3회 → 큐 적재
- 외부 복구 시 자동 재처리
- 1 시간 이상 지속 시 외부 시스템 담당자 연락

## 6. 배포 절차

### 6.1 정기 배포 (주 1회 화요일 22:00)

```bash
# 1. 사전 점검
./scripts/pre-deploy-check.sh

# 2. blue-green 배포
./scripts/deploy.sh --env=prod --strategy=blue-green

# 3. 헬스 체크 (60초 대기)
./scripts/wait-healthy.sh --timeout=60

# 4. 트래픽 전환
./scripts/switch-traffic.sh --to=green

# 5. 5분 모니터링
./scripts/post-deploy-monitor.sh --duration=300

# 6. 이전 버전 유지 (롤백 대비, 72 시간)
```

### 6.2 긴급 패치

- Sev-1 결함 → 4 시간 내 hotfix 배포 (G3 우회 가능, PM 결재 필수)
- 이후 정기 절차로 회귀 검증 보강

### 6.3 롤백

```bash
# blue-green 트래픽 전환만으로 복구 (운영 데이터 변경 없음)
./scripts/switch-traffic.sh --to=blue
./scripts/wait-healthy.sh

# DB 스키마 변경 포함 시
psql -f mapping/db/migration/rollback/U{version}__{name}.sql
```

> 컷오버 후 **72 시간** 내 긴급 롤백 가능 상태 유지 (BCP 원칙).

- **전체 DB 손상**: 풀백업 복구 + WAL 적용 (RTO ≤ 1 시간)
- **DR 사이트 전환**: secondary 활성화 (RPO ≤ 5 분)
