# Harness Assistant — ការណែនាំបំពេញបន្ថែមនៃការផ្ទៀងផ្ទាត់ (បន្តពី 07)

> **ទីតាំង**: ជំនាញជំនួយចុងក្រោយនៃលំហូរអភិវឌ្ឍន៍។ លំដាប់ **01~06 អភិវឌ្ឍន៍ → 07 ផ្ទៀងផ្ទាត់ស្តង់ដារ → 08 ណែនាំបំពេញបន្ថែម**។
> **គោលបំណង**: ទទួលលទ្ធផលផ្ទៀងផ្ទាត់ពី 07 រួច **ណែនាំអំពីអ្វីដែលត្រូវបំពេញតាមអាទិភាព** (ចម្បង) និងណែនាំសកម្មភាពបន្ទាប់នៃគម្រោងកំពុងដំណើរការ (បន្ទាប់បន្សំ)។
> **គោលការណ៍**: **ប្រើឡើងវិញដោយមិនផ្លាស់ប្តូរ** ទ្រព្យសម្បត្តិដែលមានស្រាប់ (ជំនាញ · ភ្នាក់ងារ · គំរូ 01~07)។ ជំនាញនេះទទួលបន្ទុកតែការចែកចាយ (dispatcher) និងការគ្រប់គ្រងស្ថានភាពប៉ុណ្ណោះ។
> **ឯកសាររចនា**: `docs/specs/2026-06-12-harness-assistant-design.md`

## 📘 សេចក្តីពន្យល់សង្ខេប (សូមអានមុនគេ)

**ជំនាញនេះធ្វើអ្វី?**
Skill 07 ប្រាប់ថា **"អ្វីខុស"** ប៉ុន្តែវាមិនកែអ្វីទាំងអស់ (read-only)។ Skill 08 គឺជា **ជំហានបន្ទាប់** — វាយកបញ្ជីបញ្ហានោះមកតម្រៀបតាមអាទិភាព រួចជួយអ្នកកែម្តងមួយៗ។

**ភាពខុសគ្នារវាង 07 និង 08:**

| | Skill 07 | Skill 08 |
|---|---|---|
| តួនាទី | អធិការ (រកបញ្ហា) | ជំនួយការ (កែបញ្ហា) |
| កែឯកសារ? | ទេ (read-only ដាច់ខាត) | បាទ តែ **ត្រូវសុំការអនុញ្ញាតម្តងមួយៗ** |
| លទ្ធផល | របាយការណ៍បញ្ហា | ផែនការសកម្មភាព + ការប្រៀបធៀបពិន្ទុមុន/ក្រោយ |

**របៀបទាំង ២ របស់ជំនាញនេះ:**

**① របៀបសវនកម្ម (Audit — ការប្រើប្រាស់ចម្បង)**
ដំណើរការ /07 → អានរបាយការណ៍ → បង្កើតផែនការសកម្មភាព → សួរអ្នកម្តងមួយធាតុ ("តើកែឥឡូវ? រំលង? ឬដាក់ក្នុង backlog?") → កែតែអ្វីដែលអ្នកយល់ព្រម → ដំណើរការ /07 ម្តងទៀត → បង្ហាញពិន្ទុមុន និងក្រោយ។

**② របៀបគម្រោងថ្មី (New — បន្ទាប់បន្សំ)**
តាមដានថាអ្នកបានធ្វើដល់ជំហានណាហើយ (ក្នុងឯកសារ `.harness-state.yaml`) រួចប្រាប់ថាអ្វីត្រូវធ្វើបន្ទាប់។ បើអ្នកព្យាយាមរំលងច្រកដែលមិនទាន់អនុម័ត វានឹងបញ្ឈប់អ្នក។

**⚠ ច្បាប់ដាច់ខាតពីរ:**
1. **ហាមកែជំនាញ /07 ខ្លួនឯង** — ត្រូវរក្សាគោលការណ៍ read-only របស់វា
2. **AI មិនអាចកត់ត្រាការអនុម័តច្រកជំនួសមនុស្សបានទេ** — វាណែនាំបានតែវិធីកត់ត្រាប៉ុណ្ណោះ។ ការអនុម័តគឺជាសិទ្ធិមនុស្សសុទ្ធសាធ

**គោលការណ៍អាទិភាពនៃការកែ:**
1. **FAIL (ទប់ស្កាត់ច្រក) → WARN (ណែនាំមុនច្រក) → LOW (backlog)**
2. ក្នុងកម្រិតដូចគ្នា: **សុវត្ថិភាព > ភាពតាមដានបាន > ឯកសារ**

**វាក្យសព្ទសំខាន់ៗ:**

| ពាក្យ | ន័យ |
|------|-----|
| Dispatcher | អ្នកចែកចាយ — មិនធ្វើការខ្លួនឯង តែហៅជំនាញផ្សេងឱ្យធ្វើ |
| `.harness-state.yaml` | ឯកសារកត់ត្រាថាបានធ្វើដល់ជំហានណា និងច្រកណាបានអនុម័ត |
| Backlog | បញ្ជីការងារដែលទុកធ្វើពេលក្រោយ |
| Drift | ការរសាត់ — កំណែ harness មិនត្រូវនឹងកំណែកញ្ចប់ |
| Before/After | ការប្រៀបធៀបពិន្ទុមុន និងក្រោយការកែ ដើម្បីបង្ហាញលទ្ធផលជាក់ស្តែង |
| CQ1 / CQ3 | CQ1 = ធាតុចូលចាំបាច់ (ជ្រើសរបៀប); CQ3 = ត្រូវការសិទ្ធិសម្រេចដោយមនុស្ស (អនុម័តការកែ) |

**គោលការណ៍មូលដ្ឋាន: ឯកសារពិតគឺជាការពិត។** បើឯកសារស្ថានភាពនិយាយមួយយ៉ាង តែឯកសារពិតជាមួយយ៉ាងទៀត នោះត្រូវជឿឯកសារពិត។

## 5. លក្ខណៈវិនិច្ឆ័យបញ្ចប់ (DoD)

- [ ] (សវនកម្ម) បង្ហាញផែនការសកម្មភាព + អនុវត្តអ្វីដែលបានអនុម័ត + រាយការណ៍ពិន្ទុ before/after
- [ ] (សវនកម្ម) ជំនាញ /07 និងរបាយការណ៍ដើម មិនត្រូវបានផ្លាស់ប្តូរ (ការអនុវត្តជាជំហានសរសេរដាច់ដោយឡែក)
- [ ] (ថ្មី) បង្ហាញសកម្មភាពបន្ទាប់ ១ យ៉ាងច្បាស់លាស់ (អាចចូល / មូលហេតុទប់ស្កាត់ + វិធីដោះស្រាយ)
- [ ] (ថ្មី) AI មិនកត់ត្រាការអនុម័តច្រក — គ្រាន់តែណែនាំប៉ុណ្ណោះ
- [ ] ពេលធ្វើបច្ចុប្បន្នភាពឯកសារស្ថានភាព ត្រូវបញ្ជាក់ថាត្រូវគ្នានឹងផលិតផលពិត

## 6. លក្ខណៈវិនិច្ឆ័យសំណួរ

សំណួរទៅអ្នកប្រើនៃជំនាញនេះ អនុវត្តតាមលក្ខណៈវិនិច្ឆ័យ §4.8: ការជ្រើសរបៀប · ការអនុម័តចូលជំហាន = **CQ1**, ការសម្រេចអនុវត្តការបំពេញបន្ថែម · ការបន្តច្រក = **CQ3**។ មិនបង្កើតសំណួរដែលគ្មានសញ្ញាបញ្ហាទេ។
