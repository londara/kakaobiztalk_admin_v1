# 교차 검증 리포트 #1

> **Skill**: 05 step [D] · **Date**: 2026-08-14
> **상태**: ⛔ **실행되지 않았다 / NOT PERFORMED**

---

## 1. 왜 실행되지 않았는가 / Why not

Skill 5 §2 는 교차 검증을 **"Skill 5 핵심"** 으로 규정하고, 산출물을 **다른 벤더의 LLM**
(Codex / GPT-5 / Gemini)에 입력하도록 요구한다.

**나는 다른 벤더의 모델에 접근할 수 없다.** 이 세션에는 그 경로가 존재하지 않는다.

내가 내 코드를 다시 읽는 것은 교차 검증이 **아니다**. 교차 검증의 가치는 "다른 눈"이 아니라
**다른 학습 분포·다른 실패 편향**에서 나온다. 같은 모델이 같은 코드를 다시 보면, 처음
놓친 것을 놓치는 경향도 함께 재현된다. 그것을 "교차 검증 완료"로 기록하면 **G3 게이트가
검증하지 못한 것을 검증했다고 믿게 된다** — 게이트 자체를 무력화하는 기록이다.

*Re-reading my own code is not cross-validation. Its value comes from a different training
distribution and different failure biases, not merely from a second pass. Recording a self-review
as cross-validation would make the G3 gate certify something it never examined.*

## 2. 설령 접근 가능했더라도 지금은 차단된다 / S1 would block it anyway

Skill 5 §2 의 **외부 전송 데이터 통제(S1)** 는 외부 LLM 전송 전 세 조건을 요구한다.

| S1 조건 | 현재 상태 |
|---------|----------|
| ① 시크릿·키·토큰 제거 | ❌ **위반** — `application.yml:77` 에 AES-256 키 기본값이 하드코딩되어 있다 (SR-05) |
| ② 실데이터·PII 마스킹 | ✅ 저장소에 실데이터 없음. 마스킹은 DB 함수 계층에서 수행 |
| ③ 조직 승인 모델·리전만 | ❓ **미확인** — 승인 목록을 받은 바 없다 |

**①이 위반 상태이므로 지금 저장소를 외부로 보내면 AES 키가 함께 나간다.** 규제 데이터를
다루는 시스템(전자금융감독규정·ISMS-P 대상)의 암호 키다.

즉 **SR-05 는 두 가지를 동시에 차단하고 있다**: G3 게이트(보안 결함으로서)와 교차 검증
절차(egress 전제 조건으로서). 하나의 미해결 항목이 두 게이트를 막고 있다는 사실은
SR-05 의 우선순위를 재확인해 준다.

## 3. 대체 수행한 것 / What was done instead

교차 검증 대신 **적대적 자체 리뷰**를 수행했고, **그것으로 라벨링했다**.

- 방법: 구현 시 사용한 관점(요구사항 충족)이 아니라 **"이 시스템이 어떻게 동작하지 않는가"**
  로 진입. 계층 사이의 배선(설정↔클라이언트, 필터 순서, 실행 경로)을 우선 검사.
- 결과: **SEV-1 결함 1건 + MEDIUM 1건 + LOW 3건** → [code-review-sprint-M4.md](code-review-sprint-M4.md)
- 가장 중요한 발견: **CR-01 (CSRF 토큰 전 계층 누락 → 인증 후 전면 403)**

> 이 발견은 교차 검증이 잡아야 했던 유형이다. 자체 리뷰로 잡혔다는 것은 **자체 리뷰가
> 무의미하지 않다**는 뜻이지만, **교차 검증을 대체한다는 뜻은 아니다** — 이번에 잡은 것이
> 있다는 사실은 잡지 못한 것이 없다는 근거가 되지 못한다.

## 4. CVSS 점수화 — 발견 결함 / CVSS scoring

교차 검증 결함 표가 아니라 **자체 리뷰 결함 표**임을 명시한다.

| ID | 결함 | CVSS v3.1 | 벡터 | 등급 |
|----|------|-----------|------|------|
| SR-05 | AES-256 키 하드코딩 (`application.yml:77`) | **7.5** | `AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:N` | **HIGH** |
| CR-01 | CSRF 토큰 누락 → 전면 403 | **N/A** | fail-closed 기능 정지 (오수정 시 **8.8**) | SEV-1 기능 |
| AMB-M01 | 테넌트 매핑 컬럼 미검증 | **6.5 (조건부)** | `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N` | 가정이 틀릴 경우만 |
| CR-02 | 반출 엔드포인트 속도 제한 없음 | **4.3** | `AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:N/A:L` | MEDIUM |
| CR-03/04/05 | 프론트 blob 해제 / 감사 시점 / 공백 선행 | — | — | LOW |

**SR-05 점수 근거**: 저장소가 비공개라고 가정하여 `AV:L / PR:L`. 공개 저장소라면
`AV:N / PR:N` 으로 **9.1 (CRITICAL)** 이 된다. 저장소 공개 여부는 확인하지 못했으므로
**보수적이지 않은 쪽이 아니라 보수적인 쪽으로** 가정을 명시한다.
`S:C` — 키가 OTP 비밀을 복호화하므로 인증 경계를 넘어 영향이 확산된다.

**CVSS ≥ 7.0 결함이 1건 존재** → Skill 5 §2 등급표에 따라 **차단(HIGH)**.

| # | 결정 사항 | 선택지 |

| 1 | 교차 검증을 어떻게 수행할 것인가 | (a) 사내/승인 모델 제공 (b) 외부 벤더 승인 + SR-05 선행 해소 (c) **명시적 면제 결재** — 그 경우 G3 는 교차 검증 없이 통과했다는 사실이 기록되어야 한다 |

> 결정했다"로 기록된다. 두 기록의 차이가 이 문서가 존재하는 이유다.
