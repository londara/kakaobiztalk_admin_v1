### 2-3 이 가장 중요하다 / The one that matters

CSV 에는 **60행이지만 요구사항은 52개**다. 8개 ID 가 복수 산출물을 가져 여러 행으로
존재한다(정상 — 한 요구사항이 여러 파일로 충족될 수 있다). 행을 세면 **90% 가 아니라
92% 라는 잘못된 수치**가 나온다.

이것은 sprint L6 에서 PM 이 지적한 것과 **같은 종류의 실수**다(59 → 62). 그때는 요구사항
ID 를 임의로 추가한 것이었고, 이번은 집계 단위를 잘못 잡을 뻔한 것이다. 공통 원인은
**"기준선은 고정되어 있고 진행률은 그 기준선에 대해서만 의미가 있다"** 는 규칙을 매번
다시 확인하지 않은 것이다.

*Counting rows instead of requirements would have reported 92% instead of 90% — the same class of
error the PM caught at L6.*
