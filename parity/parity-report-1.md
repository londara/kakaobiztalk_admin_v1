# Parity 리포트 #1

> **Skill**: 05 step [A] · **Date**: 2026-08-14 · **Agent**: `qa-engineer`
> **상태**: ⛔ **바이트 단위 Parity 는 수행 불가 / IMPOSSIBLE, not merely unperformed**

---

## 1. 왜 불가능한가 / Why impossible

TEST-PLAN §3 은 마이그레이션 프로젝트에 **"바이트 단위 동치"** 를 요구한다. 이 요구는
**실행 가능한 레거시**를 전제한다.

| 필요 조건 | 상태 |
|-----------|------|
| Jex 런타임 (WebCash 사유 프레임워크) | ❌ 없음 |
| 레거시 애플리케이션 서버 | ❌ 없음 |
| `BIZTALK_DB` 운영 데이터 | ❌ 없음 |
| DB 함수 `decrypt()` / `masking()` | ❌ 없음 |
| 대조용 입력·출력 샘플 | ❌ 없음 |

우리가 가진 것은 **소스 코드뿐**이다(RISK-001). 두 시스템의 출력을 비교하려면 두 시스템이
모두 실행되어야 하는데, 한쪽이 존재하지 않는다.

`scripts/parity-check.sh` 는 **사용 불가 상태로 남아 있다** — 삭제하지 않은 이유는 레거시
환경이 확보되면 필요하기 때문이며, 그때까지 실행하면 무의미한 통과를 보고한다.

## 2. 더 근본적인 문제 — Parity 를 원하지 않는다

**레거시에는 확인된 결함이 19건 있다.** 바이트 단위 동치를 달성하면 그 19건을 **모두 재현**해야
한다.

| Defect | 레거시 동작 | Parity 를 달성하려면 |
|--------|------------|---------------------|
| D2 | 메시지키 검색이 **항상 0건** | 검색이 동작하지 않아야 한다 |
| D5 | 연도를 **5자리**로 출력 (`YYYYY`) | 잘못된 날짜를 출력해야 한다 |
| D9 | 19필드 선언, **8필드 반환** | 11개 필드를 숨겨야 한다 |
| D1 | 목록 서비스 **미인증** | 인증을 제거해야 한다 |
| L2 | 비밀번호를 **무솔트 SHA-256** 으로 저장 | Argon2id 를 되돌려야 한다 |

**즉 Parity 와 결함 수정은 상호 배타적이다.** 19건을 수정하기로 한 결정(REQUIREMENTS-SPEC
G1 승인)은 곧 **바이트 Parity 를 포기하기로 한 결정**이었다.

*Byte parity and defect correction are mutually exclusive. Approving the fix of 19 legacy defects
was itself the decision to abandon byte parity.*

## 3. 대체 수행 — 명세 Parity / Spec parity instead

TEST-PLAN §7 에 정의한 대체 기준을 적용했다: **"레거시 소스가 의도한 동작"과의 일치**
(실제 동작이 아니라 의도).

| 영역 | 방법 | 결과 |
|------|------|------|
| SQL 이식 | `IDO.*.xml` 을 near-verbatim 이식, 변경 줄마다 `-- FIX Dn:` | ✅ 4개 매퍼, 델타만 리뷰 가능 |
| 라우팅 | 4-way 테이블 선택을 `<choose>` 로 재현 | ✅ 48건 실행 검증 |
| 상태·유형 코드 | 레거시 코드값 그대로 (`1`~`6`, `AT`/`FT`) + 미인식 값 원문 노출 | ✅ 실행 검증 |
| 시간대 게이팅 | Jex 런타임의 `tmUseYn`/`strTm`/`endTm` 의미 재현 (`240000` 관용구 포함) | ✅ 25건 실행 검증 |
| 그리드 컬럼 | 12컬럼 순서·라벨 유지 (D3 는 **의도적 불일치** — 라벨/컬럼 교차를 바로잡음) | ✅ 프론트 테스트 |
| 페이징 | 레거시는 주석 처리(D7) → **의도된 동작**(주석 코드가 존재)을 복원 | ✅ |

### 검증되지 않은 이식 / Unverified ports

| 항목 | 이유 |
|------|------|
| SQL 델타 4건 (D2·D4·D5·D6) | **DB 없이 SQL 을 실행할 수 없다.** 주석으로 리뷰 가능하게만 남김 |
| 상세 19필드 (AMB-M02) | 11개 컬럼의 **존재 자체가 미확인** |
| 테넌트 컬럼 (AMB-M01) | 미확인 |

## 4. 판정

| 기준 | 결과 |
|------|------|
| 바이트 단위 Parity | **수행 불가 · 영구** (레거시 실행 환경 없음 + 결함 수정과 배타) |
| 명세 Parity | **부분 달성** — 실행 검증 가능한 영역은 완료, SQL 영역은 미검증 |

**권고**: TEST-PLAN §3 의 "바이트 단위 동치" 항목을 **이 프로젝트에서는 적용 불가**로
공식 기록하고, §7 명세 Parity 를 정본 기준으로 승격할 것. PM 결재 대상 — 표준 문구를
그대로 두면 이후 감사에서 "Parity 미수행"이 결함으로 보이지만, 실제로는 **의도적이고
불가피한 설계 결정**이다.
